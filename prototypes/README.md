# Iteration 1 prototype

> **Status:** Throwaway. This is an exploration aid, not the start of the product. It decides no technology.

A static, clickable page that shows the example models in `examples/`, driven only by the meta-model and the presentation files. Changes live in memory only: reloading the page (or **Reset**) restores the original state. Write-back to sources is simulated.

## Start

```
python3 tools/build_bundles.py          # after changing anything in examples/
python3 -m http.server -d prototypes 8000
```

Then open <http://localhost:8000>. In a GitHub Codespace, open the forwarded port 8000.

## What to try

1. Switch between the smart home and the enterprise model, and between views.
2. Open a connection at the second site and look at its technical path.
3. Rename a device that comes from Home Assistant: the change waits in **Pending changes**.
4. Use **Simulate source change** on the same attribute: the source wins, and "discard" is preselected for the corvia change.
5. Tick **fail** for a row and run the check: the row stays with status "failed".
6. Open a list view (e.g. **All devices**): search, sort by clicking a column heading, filter per column, choose columns under **Columns**, and edit values in place. Relationship columns are marked with ↔.
7. Edit **notes** of a device: the field takes Markdown (bold, lists, links) and is shown formatted.
8. Open the **business-letter** model: the letter structure tree goes down to parts inside parts. Open the "contains document" relationship of the welcome letter and the SEPA mandate to see its condition.

## Files

- `lib/model.js`: navigation (titles, relationships, edges, drill-down, trees)
- `lib/deltas.js`: pending changes and the simulated check (design D5)
- `lib/table.js`: list columns, search, filter and sort
- `lib/markdown.js`: safe Markdown subset for text attributes
- `app.js`: the page; contains no type names
- `data/`: generated by `tools/build_bundles.py`, do not edit

Tests: `node --test 'prototypes/tests/*.test.mjs'`
